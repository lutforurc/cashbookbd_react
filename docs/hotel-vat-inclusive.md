# হোটেল বিলে VAT Including মোড — নিয়ম ও বাস্তবায়ন নির্দেশিকা

তারিখ: ২৭ অক্টোবর ২০২৬
অবস্থা: **কোড লেখা শেষ (ফ্রন্টএন্ড + ব্যাকএন্ড) — শুধু স্কিমা প্যাচ চালানো ও স্টেজিং পরীক্ষা বাকি**

---

## ১. সারসংক্ষেপ

সিস্টেমে এখন শুধু **VAT Excluding** আছে। অর্থাৎ রেট কার্ডে যে দাম লেখা, সেটা ঘরের ভাড়া;
সার্ভিস চার্জ ও ভ্যাট তার **উপরে** যোগ হয়। কিন্তু সব হোটেল একভাবে দাম বলে না —

| | রেট কার্ডে ৩,০০০ লিখলে | অতিথি দেয় |
|---|---|---|
| **VAT Excluding** | ঘর ৩,০০০ + সার্ভিস + ভ্যাট | ৩,৬২২.৫০ |
| **VAT Including** | পুরো দামই ৩,০০০ | ৩,০০০.০০ |

⚠️ **এটা করের নিয়ম নয়, দাম বলার ধরন।** দুই মোডেই ভ্যাট একই হারে, একই সময়ে, একই খাতায়
যায়। পার্থক্য শুধু একটাই — রেট কার্ডের সংখ্যাটা করের **আগের** দাম, না করের **সহ** দাম।

তাই:

- দুই মোডে **একই খাতা**, **একই রিপোর্ট**, **একই ভাউচার** — শুধু ভাগ-বাটোয়ারার অঙ্ক আলাদা।
- দুই মোড একসাথে চালানোর দরকার নেই; এটা **প্রতি ব্রাঞ্চের একটা সেটিং**।
- পুরোনো বিল **কখনো** বদলায় না — প্রতিটা বিল লাইন নিজের অঙ্ক নিজে মনে রাখে।

## ২. নিয়ন্ত্রণ কোথায়

**Add / Edit Branch → Hotel Setup → VAT Setup** — দুটি রেডিও কার্ড।

| | |
|---|---|
| ফাইল | `src/components/modules/branch/AddBranch.tsx` |
| সেকশন | Hotel Setup স্টেপের `VAT Setup` ব্লক |
| মেটা কী | `hotel_vat_mode` |
| মান | `exclusive` (ডিফল্ট) অথবা `inclusive` |
| সংরক্ষণ | `metas`-এ, ব্রাঞ্চের সাথে — `hotel_check_in_time` ইত্যাদির মতোই |

✅ **ব্যাকএন্ডে যা যা লেগেছে — সবই করা হয়েছে** (`D:\www\cashbook_api`):

1. ✅ **গ্রহণ** — `BranchController::updateBranch()`-এর `$metaData`-তে
   `hotel_vat_mode` যোগ হয়েছে; মান `ItemTax::normalizeMode()` দিয়ে ছাঁকা।
2. ✅ **ফিরিয়ে দেওয়া** — `getBranchEdit()`-এ
   `$branch->hotel_vat_mode = ItemTax::vatMode((int) $branch->id)`।
3. ✅ **ডিফল্ট** — `ItemTax::vatMode()`: না থাকলে / খালি হলে / অচেনা হলে `exclusive`।
4. ✅ সুইচ বদলানোর পরের লাইন থেকেই কার্যকর — `FolioBilling::billNights()`,
   `projectedTotals()`, `FolioController::addCharge()`।

⚠️ **প্রথমে যেটা করতে হবে:** `hotel_booking_folio_details.vat_mode` কলামটা এখনো
আপনার ডেটাবেসে নেই। `AddUnitTypeToBuildingUnits` কমান্ডের `runHotelVatModeSchema()`
এটা যোগ করে — ওই স্ক্রিপ্ট চালানো পর্যন্ত Inclusive ব্রাঞ্চে বিল করলে "Unknown column"
এরর আসবে।

## ৩. হিসাব

### ৩.১ VAT Excluding (বর্তমান, অপরিবর্তিত)

```
base    = qty × rate                 (ঘরের ভাড়া)
service = base × SC%                 (সার্ভিস চার্জ)
VAT     = (base + service) × VAT%    (ভ্যাট সার্ভিস চার্জের উপরেও)
total   = base + service + VAT
```

### ৩.২ VAT Including (নতুন)

রেট কার্ডের দামটাই **অতিথির দেওয়া মোট**। সেখান থেকে ভাড়া, সার্ভিস চার্জ ও ভ্যাট
**উল্টো দিকে** বের করতে হবে।

```
T       = qty × rate                       (রেট কার্ডের দাম — এটাই মোট)
base    = T / ((1 + SC%) × (1 + VAT%))     (ঘরের ভাড়া)
service = base × SC%                       (সার্ভিস চার্জ)
VAT     = T − base − service               (বাকিটা ভ্যাট)
```

⭐ **ভ্যাট কেন "বাকিটা"?** কারণ `base + service + VAT` সবসময় **হুবহু T** হবে — এক
পয়সাও এদিক-ওদিক হবে না। `base` ও `service`-কে ২ দশমিক পর্যন্ত রাউন্ড করে, ভ্যাটকে
**অবশিষ্ট** হিসেবে রাখলে রেট কার্ডে যা লেখা অতিথি ঠিক তাই দেয়। ভ্যাটকে আলাদা করে
রাউন্ড করলে বিল রেট কার্ডের চেয়ে এক পয়সা কম-বেশি হয়ে যেত।

ভ্যাটের ভিত্তি কিন্তু বদলায়নি — যাচাই করে দেখা যায়:

```
(base + service) × VAT% = base × (1 + SC%) × VAT% = T − base − service  ✓
```

অর্থাৎ **"সার্ভিস চার্জের উপরেও ভ্যাট"** নিয়মটা দুই মোডে একই আছে।

### ৩.৩ পাশাপাশি উদাহরণ

৩,০০০ টাকার ঘর, সার্ভিস চার্জ ৫%, ভ্যাট ১৫%:

| | VAT Excluding | VAT Including<br>(রেট কার্ড অপরিবর্তিত) | VAT Including<br>(রেট কার্ড রূপান্তরিত) |
|---|---:|---:|---:|
| রেট কার্ডে লেখা | ৩,০০০.০০ | ৩,০০০.০০ | **৩,৬২২.৫০** |
| ঘরের ভাড়া (base) | ৩,০০০.০০ | ২,৪৮৪.৪৭ | ৩,০০০.০০ |
| সার্ভিস চার্জ ৫% | ১৫০.০০ | ১২৪.২২ | ১৫০.০০ |
| ভ্যাট ১৫% | ৪৭২.৫০ | ৩৯১.৩১ | ৪৭২.৫০ |
| **অতিথি দেয়** | **৩,৬২২.৫০** | **৩,০০০.০০** | **৩,৬২২.৫০** |

⭐ **তৃতীয় কলামটাই আসল কথা** — নিচের §৫ দেখুন। রেট কার্ড রূপান্তর করলে Inclusive
মোডে **খাতার প্রতিটি সংখ্যা হুবহু আজকের সমান** থাকে।

### ৩.৪ প্রতি **লাইনে** ভাগ হবে, প্রতি বিলে নয়

সিস্টেম প্রতি রাতকে আলাদা লাইন হিসেবে বিল করে, আর প্রতিটা লাইন নিজের base / service /
VAT / মোট মনে রাখে। তাই ভাগ-বাটোয়ারাও **প্রতি লাইনে** হবে।

২ রাত × ৩,০০০ (Inclusive):

```
প্রতি রাত : 2,484.47 + 124.22 + 391.31 = 3,000.00
দুই রাত   : 4,968.94 + 248.44 + 782.62 = 6,000.00   ✓
```

⚠️ বিলের মোট ৬,০০০-কে একবারে ভাগ করলে হতো `4,968.94 + 248.45 + 782.61` — যোগফলও
৬,০০০, কিন্তু **প্রতি লাইনে যা সংরক্ষিত আছে তার সাথে মিলত না**। পরে বিল রিপ্রিন্ট করলে
অঙ্ক বদলে যেত। তাই: **লাইন যেভাবে বিল হয়েছে, সেভাবেই ভাগ — কখনো বিলের মোট থেকে
পুনর্গণনা নয়।**

### ৩.৫ রাউন্ডিং

| | |
|---|---|
| প্রতি লাইন | base ও service ২ দশমিক পর্যন্ত; ভ্যাট = T − base − service (অবশিষ্ট) |
| বিলের মোট | আগের নিয়মই — লাইনগুলো যোগ → gross → ডিসকাউন্ট → net → **একবার** নিকটতম টাকায় |

⚠️ Inclusive-এ গোলমালের জায়গা একটাই: রেট কার্ডে অর্ধ টাকা থাকলে (যেমন ২,৫০০.৫০ × ৩)
টাকায় রাউন্ড করার পর অতিথি রেট কার্ডের চেয়ে আধা টাকা বেশি-কম দিতে পারে। তখন
**রাউন্ডিং লাইনটা ছাপতে হবে** (শূন্য হলে ছাপবে না) — নাহলে অতিথি দেখবে কার্ডে এক দাম,
বিলে আরেক দাম। Exclusive-এ এই সমস্যা নেই, কারণ সেখানে রেট কার্ডই মোট নয়।

চাইলে বিকল্প নিয়মও নেওয়া যায় — Inclusive ব্রাঞ্চে টাকায় রাউন্ড না করে **পয়সা
পর্যন্ত** রাখা, যাতে মোট হুবহু রেট কার্ডের সমান হয়। তবে তখন দুই ব্রাঞ্চে দুই রাউন্ডিং
নিয়ম চলবে, যা হিসাব মেলানোর সময় প্রশ্ন তুলবে। **সুপারিশ: একই নিয়ম রাখুন, আর
রাউন্ডিং nonzero হলে বিলে দেখান।**

### ৩.৬ ডিসকাউন্ট

নিয়ম **বদলায় না** — লাইনগুলো যোগ → gross → gross থেকে ডিসকাউন্ট → net।

⚠️ Inclusive-এ এর অর্থ: ডিসকাউন্ট আসে এমন দাম থেকে যার **ভেতরে ভ্যাট আছে**। কিন্তু
সরকারের পাওনা ভ্যাট কমে না — পূর্ণ ট্যারিফের উপরই ভ্যাট দিতে হবে, পার্থক্যটা হোটেল
নিজের লাভ থেকে বহন করবে। এটা Exclusive-এও আজ ঠিক এভাবেই আছে (§37), তাই কোডে নতুন
কিছু করতে হবে না — শুধু বুঝে নিতে হবে।

### ৩.৭ শূন্য হার

| অবস্থা | ফল |
|---|---|
| ভ্যাট ০% (যেমন লন্ড্রি) | `base = T / (1 + SC%)`, `service = base × SC%`, `VAT = 0` |
| সার্ভিস চার্জ ০% | `base = T / (1 + VAT%)`, `service = 0`, `VAT = T − base` |
| দুটোই ০% | `base = T`, বাকি সব ০ |
| ঋণাত্মক/অসম্ভব হার | সার্ভারে প্রত্যাখ্যান (আজ যেমন আছে) |

## ৪. ডেটা মডেল ও ব্যাকএন্ড চুক্তি

### ৪.১ ব্রাঞ্চ মেটা

```
key    : hotel_vat_mode
values : 'exclusive' | 'inclusive'
default: 'exclusive'      (না থাকলে, খালি হলে, অচেনা হলে)
```

`metas` টেবিলে ব্রাঞ্চ-ভিত্তিক, `hotel_check_in_time`-এর পাশেই। নতুন টেবিল বা কলাম লাগবে না।

### ৪.২ প্রতিটি বিল লাইনে মোডটা **সংরক্ষণ** করতে হবে

⚠️ এটাই সবচেয়ে জরুরি স্কিমা পরিবর্তন। আজ প্রতিটা লাইন নিজের **রেট, base, service,
VAT** মনে রাখে — ঠিক তেমনি **কোন মোডে ভাগ হয়েছিল** সেটাও রাখতে হবে।

```
hotel_booking_folio_details
  + vat_mode  varchar(16) not null default 'exclusive'
```

✅ যোগ হয়েছে — `AddUnitTypeToBuildingUnits::runHotelVatModeSchema()`; মডেলের
`$fillable`-এ `vat_mode`, আর `line()` প্রতিটা লাইনে মানটা লিখে দেয়।

কেন:

- ব্রাঞ্চের সেটিং পরে বদলালে পুরোনো বিল **পুনর্গণনা** করলে অঙ্ক বদলে যাবে।
- বিল রিপ্রিন্ট, রিফান্ড, ডিসকাউন্ট-পরবর্তী পোস্টিং — সবই সংরক্ষিত অঙ্ক থেকে চলে।
- পুরোনো সব লাইনে মাইগ্রেশনে `'exclusive'` বসবে — আজকের আচরণই।

### ৪.৩ কোথায় কী বদলেছে

| | |
|---|---|
| রেট কোনটা | `App\Services\Hotel\ItemTax` — রেট অপরিবর্তিত; `vatMode()` / `normalizeMode()` নতুন |
| ভাগ-বাটোয়ারা | `BookingFolioDetail::line()` — এখানেই একমাত্র অঙ্ক, ৯ম প্যারামিটার `$vatMode` |
| বিলের মোট | `BookingFolioDetail::totalsOf()` — সংরক্ষিত অঙ্ক যোগ করে, মোড জানে না |
| পোস্টিং | `HotelVoucher::postFolio()` — **অপরিবর্তিত** |
| ডিসকাউন্ট | `FolioController::discount()` — **অপরিবর্তিত** |

প্রকৃত সিগনেচার:

```php
BookingFolioDetail::line(
    int $companyId, int $branchId, string $chargeType,
    float $quantity, float $unitRate, string $onDate,
    float $vatRate = 0.0, float $serviceRate = 0.0,
    string $vatMode = ItemTax::MODE_EXCLUSIVE
): array
```

ডাকা হয় তিন জায়গা থেকে, তিনটাতেই মোডটা ব্রাঞ্চ থেকে পড়ে পাস করা হয়:
`FolioBilling::billNights()`, `FolioBilling::projectedTotals()`,
`FolioController::addCharge()`।

### ৪.৪ খাতা (ledger)

নিয়ম বদলায় না:

```
Dr  Party (A/R) বা Cash/Bank     net
    Cr  Room Rent Income          base
    Cr  Service Charge Income     service
    Cr  VAT Payable               VAT
    Dr  HOTEL_DISCOUNT_ALLOWED    discount
    Dr/Cr Rounding                rounding
```

Inclusive-এ শুধু **অঙ্কগুলো** আলাদা — খাত, দিক, নিয়ম সব একই।

| `DescribesProperty::hotelTimes()` | `vat_mode` (হল স্ক্রিনের `times`-এ, `BookingController::halls()` থেকে) |

বাকি (লেখার সুবিধার জন্য, বিলের অঙ্কে কোনো প্রভাব নেই): Room Types, Charges —
ওখানকার লেবেল দুই মোডেই সত্য, তাই এখনই ভাঙে না।

## ৫. রেট কার্ড রূপান্তর — সবচেয়ে বড় সতর্কতা

⚠️ **মোড বদলালে রেট কার্ড নিজে থেকে বদলায় না।**

একটা হোটেল আজ ৩,০০০-এর ঘরে ৩,৬২২.৫০ নিচ্ছে। Inclusive চালু করল, রেট কার্ডে ৩,০০০-ই
রইল — এখন থেকে সে **৩,০০০** নেবে। ভ্যাট ও সার্ভিস চার্জ তবু দিতে হবে, কিন্তু সেই
একই টাকা থেকে। অর্থাৎ গ্রহণ **১৭% কমে যাবে**, কোনো নোটিস ছাড়াই।

তাই Inclusive চালু করার আগে একটা সিদ্ধান্ত লাগবে:

**ক) রেট কার্ড রেখে দেওয়া** — হোটেল চায় অতিথি কম দিক (বাজারের সাথে পাল্লা দিতে)।
কোনো কাজ নেই, শুধু সেটিং বদলান।

**খ) রেট কার্ড রূপান্তর করা** — গ্রহণ আজকের সমান রাখতে চায়। তাহলে প্রতিটা রেট
`(1 + SC%) × (1 + VAT%)` দিয়ে গুণ করতে হবে:

```
নতুন রেট = পুরোনো রেট × (1 + 0.05) × (1 + 0.15) = পুরোনো রেট × 1.2075
৩,০০০ × 1.2075 = ৩,৬২২.৫০
```

এতে Inclusive-এ ভাগ করলে হুবহু পুরোনো অঙ্কগুলোই ফেরে (উপরের §৩.৩-এর তৃতীয় কলাম)।

⚠️ রূপান্তরটা করলে যা **কখনো** করা যাবে না:

- `booking_folio_details`-এর পুরোনো লাইন বদলানো
- পুরোনো বিলের অঙ্ক পুনর্গণনা করা
- চুপচাপ পেছনের দরজায় ডেটা বদলে দেওয়া

সুপারিশ: আলাদা এক-বারের স্ক্রিপ্ট, **dry run** সহ — পুরোনো রেট → নতুন রেটের তালিকা
দেখিয়ে অনুমোদনের পর লেখে, আর শুধু `hotel_room_types.default_whole_rent`,
`default_seat_rent` ও `hotel_booking_charge_types.default_rate`-এ হাত দেয়। ইতিমধ্যে
চলমান বুকিংয়ের নাইট রো-তে হাত দেবে না।

## ৬. রিপোর্টে যা দেখতে পাবেন

| | Exclusive | Inclusive (রেট অপরিবর্তিত) | Inclusive (রেট রূপান্তরিত) |
|---|---:|---:|---:|
| অতিথির কাছ থেকে | ৩,৬২২.৫০ | ৩,০০০.০০ | ৩,৬২২.৫০ |
| ঘর ভাড়া আয় | ৩,০০০.০০ | ২,৪৮৪.৪৭ | ৩,০০০.০০ |
| সার্ভিস চার্জ আয় | ১৫০.০০ | ১২৪.২২ | ১৫০.০০ |
| ভ্যাট দায় | ৪৭২.৫০ | ৩৯১.৩১ | ৪৭২.৫০ |

⚠️ Inclusive হোটেলে "ঘর ভাড়া আয় কমে গেছে" দেখে আতঙ্কিত হওয়ার কিছু নেই — **গ্রহণও
কমেছে**। রূপান্তর করলে দুটোই আজকের সমান থাকে। রিপোর্টে তাই **গ্রহণ (gross collected)**
পাশে দেখানো ভালো।

## ৯. পরীক্ষার তালিকা (staging)

1. ব্রাঞ্চে Inclusive সেট → সেভ → রিলোড: এখনো Inclusive দেখায়।
2. ডেটাবেসে অচেনা মান (`xyz`) বসিয়ে রিলোড: স্ক্রিন Exclusive দেখায়, বিলও Exclusive।
3. ১ রাত, ৩,০০০, SC ৫%, VAT ১৫%, Inclusive: `2,484.47 / 124.22 / 391.31 / 3,000.00`।
4. ২ রাত: লাইন দুটোর যোগফল হুবহু `6,000.00`।
5. একই বিল Exclusive ব্রাঞ্চে: `3,000.00 / 150.00 / 472.50 / 3,622.50` — অপরিবর্তিত।
6. থাকার মাঝে মোড বদল: পুরোনো রাত অপরিবর্তিত, নতুন রাত Inclusive; ভাউচার ব্যালান্স;
   পুরোনো বিলের রিপ্রিন্ট অভিন্ন।
7. Inclusive বিলে ১০% ডিসকাউন্ট: ভ্যাট অঙ্ক অপরিবর্তিত, ডিসকাউন্ট খাত ঠিক, গ্রাহকের
   দেনা = net।
8. রেট বদলে আবার রিপ্রিন্ট: অভিন্ন।
9. রিপোর্ট: base + service + VAT = collected gross (ডিসকাউন্ট ছাড়া)।
10. রিফান্ড: সংরক্ষিত ভ্যাটসহ উল্টে যায়।
11. খাতা: পোস্টিং ব্যালান্স করে, আবার চাপলে কিছু পোস্ট হয় না।
12. রাউন্ডিং nonzero হলে বিলে রাউন্ডিং লাইন দেখা যায় (Inclusive)।
