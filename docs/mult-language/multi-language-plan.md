# বহুভাষা (Multi-language) পরিকল্পনা

**তারিখ:** 17/11/2026
**অবস্থা:** পরিকল্পনা, এখনো কোনো কোড লেখা হয়নি

---

## ১. লক্ষ্য

- সফটওয়্যার এখন পুরোটা ইংরেজিতে। **ইংরেজি সবসময় ডিফল্ট ও বাধ্যতামূলক থাকবে।**
- প্রতিটা কোম্পানি ইংরেজির সাথে **একটা নিজের ভাষা (Local Language)** বেছে নেবে: বাংলা (ফন্ট NikoshBAN), আরবি বা পরে যোগ করা যেকোনো ভাষা।
- ইউজার যেকোনো সময় এক ক্লিকে **English ↔ Local** বদলাতে পারবে।
- শুধু স্ক্রিনের লেবেল নয়, **ইউজারের লেখা ডাটাও** (Chart of Account, Customer, Supplier, Product ইত্যাদি) Local ভাষায় লেখা ও দেখা যাবে।

## ২. মূল সিদ্ধান্ত

### ২.১ ডাটা: `name` + `name_local`

প্রতিটা অনুবাদযোগ্য টেবিলে দুটো ঘর:

| কলাম | বাধ্যতামূলক | কী থাকবে |
|---|---|---|
| `name` | **হ্যাঁ** | ইংরেজি নাম, এখন যেমন আছে |
| `name_local` | না | কোম্পানির Local ভাষায় নাম |

- কলাম **ভাষার নামে নয়** (`name_bn`, `name_ar` নয়)। একটাই `name_local`। কোন ভাষা সেখানে লেখা হবে, তা ঠিক করে কোম্পানির `local_language` সেটিং।
- বাংলাদেশের ক্লায়েন্ট: `name` = Rahim Traders, `name_local` = রহিম ট্রেডার্স।
  সৌদির ক্লায়েন্ট: `name` = Rahim Traders, `name_local` = رحيم للتجارة।
- **২০টা ভাষা হলেও কলাম একটাই।** নতুন ভাষা = `languages` তালিকায় একটা সারি, একটা ফন্ট আর লেবেলের একটা অনুবাদ ফাইল। ডাটাবেসের গঠন বদলাবে না।
- এটা কাজ করে কারণ প্রতিটা ক্লায়েন্টের ডাটাবেস আলাদা (`docs/tenant-model-is-per-client-database-copy.md`), আর বাস্তবে একটা কোম্পানি ইংরেজি ও একটা স্থানীয় ভাষাই ব্যবহার করে।

### ২.২ স্ক্রিনের লেবেল: ভাষাভিত্তিক অনুবাদ ফাইল

মেনু, বাটন, বার্তা ডাটাবেসের ডাটা নয়, সফটওয়্যারের অংশ। এগুলো থাকবে `locales/en`, `locales/bn`, `locales/ar` ফাইলে। প্রতিটা ভাষার একটা করে ফাইল-সেট, কোড বা ডাটাবেস বদলায় না।

### ২.৩ নিয়ম (সব ধাপে প্রযোজ্য)

1. **ইংরেজি সবসময় থাকবে।** প্রতিটা লেবেল আর প্রতিটা `name` ইংরেজিতে থাকতেই হবে।
2. **Local না থাকলে ইংরেজি দেখাবে।** কোনো লেখা কখনো ফাঁকা দেখাবে না। অনুবাদ অর্ধেক হলেও অ্যাপ পুরোপুরি চলে।
3. **কোন ভাষা প্রযোজ্য হবে, তার ক্রম:** ইউজারের বাছাই → শাখার ডিফল্ট → English।
4. **অঙ্ক, কোড, মোবাইল, ইমেইল, TIN/BIN অনুবাদ হবে না।** ডাটাবেসে অঙ্ক সবসময় ইংরেজি লিপিতে।

### ২.৪ সীমাবদ্ধতা (জেনে নেওয়া)

| সীমাবদ্ধতা | সমাধান |
|---|---|
| এক কোম্পানিতে একসাথে ইংরেজি + ১টার বেশি ভাষা চলবে না | খুব বিরল। দরকার হলে শুধু সেই ক্লায়েন্টের জন্য পরে একটা অনুবাদ টেবিল যোগ করা যাবে, `name_local` তখনও থাকবে |
| Local Language পরে বদলালে পুরনো `name_local` আগের ভাষাতেই থেকে যায় | কোনো `name_local` লেখা হয়ে গেলে Local Language বদলানো আটকে দিন, অথবা বদলানোর আগে "সব Local নাম মুছে যাবে / নতুন করে লিখতে হবে" সতর্কবার্তা দিন |

## ৩. বর্তমান অবস্থা

## ৪. ডাটাবেস

### ৪.১ `languages` (বিদ্যমান টেবিল বাড়ানো)

| কলাম | ধরন | উদাহরণ | মন্তব্য |
|---|---|---|---|
| code | varchar(10), unique | `en`, `bn`, `ar` | |
| name | varchar | Bangla | ইংরেজিতে নাম |
| native_name | varchar | বাংলা | ভাষা বদলানোর বোতামে দেখাবে |
| font_family | varchar, null | NikoshBAN | null = Satoshi |
| font_file | varchar, null | `/fonts/NikoshBAN.woff2` | |
| digits | enum(`latin`,`native`) | `native` | এই ভাষার নিজস্ব অঙ্ক আছে কি না |
| direction | enum(`ltr`,`rtl`) | `ltr` | আরবি/উর্দুর জন্য `rtl` |
| is_active | tinyint | 1 | |

শুরুর ডাটা: `en`, `bn`। পরে `ar` ইত্যাদি শুধু সারি যোগ করে।

### ৪.২ কোম্পানি ও শাখার সেটিং

**কোম্পানি (company settings):**

| ঘর | মন্তব্য |
|---|---|
| local_language | `null` (শুধু ইংরেজি) / `bn` / `ar` … — `name_local` কোন ভাষায়, তা এটাই ঠিক করে |

**শাখা (`branches`):**

| ঘর | মান | মন্তব্য |
|---|---|---|
| ui_language | `en` / `local` | শাখার স্ক্রিনের ডিফল্ট |
| print_language | `en` / `local` | ইনভয়েস/রিপোর্টের ডিফল্ট |
| digit_style | `auto` / `latin` / `native` | Local ভাষায় বাংলা অঙ্ক দেখাবে কি না |

`local_language` null হলে শাখার এই ঘরগুলো লুকানো থাকবে, সব আজকের মতো ইংরেজিতে চলবে।

### ৪.৩ `users.lang`

আগে থেকেই আছে। মান হবে `null` (শাখার ডিফল্ট মানবে) / `en` / `local`। আগের সব ইউজারের মান `null` করে দিন, যাতে কারও স্ক্রিন হঠাৎ না বদলায়।

### ৪.৪ `name_local` কলাম — কোন টেবিলে কোন ঘর

প্রতিটা টেবিলে `varchar`, `null`, মূল ঘরের সমান দৈর্ঘ্য, `utf8mb4`। সার্চের জন্য index।

| টেবিল | নতুন ঘর |
|---|---|
| Chart of Account (`acc_coa_level1s` … `acc_coa_level4s`) | `name_local` |
| Customer / Supplier | `name_local`, `address_local` |
| Product | `name_local`, `description_local` |
| Category, Brand, Unit | `name_local` |
| Employee, Designation, Department | `name_local` |
| Bank, Warehouse, Branch | `name_local`, `address_local` |
| Company (প্যাডের জন্য) | `name_local`, `address_local` |
| Hotel building/room, Hall | `name_local` |

নিয়ম: অনুবাদযোগ্য প্রতিটা ঘরের পাশে একটা `<field>_local`। নতুন টেবিল বানালে একই নিয়ম।

### ৪.৫ `ui_translations` — ক্লায়েন্টের নিজের লেবেল (ঐচ্ছিক, ধাপ ৮)

| কলাম | উদাহরণ |
|---|---|
| lang | `bn` |
| key | `booking.summary.advance` |
| value | অগ্রিম |

স্ট্যান্ডার্ড অনুবাদ সফটওয়্যারের সাথে ফাইলে যায়। কোনো ক্লায়েন্ট নিজে কোনো লেবেল বদলালে শুধু সেটা এই টেবিলে থাকবে এবং ফাইলের লেখার উপরে বসবে।

## ৫. ফ্রন্টএন্ড

### ৫.১ লেবেলের অনুবাদ লাইব্রেরি ও ফাইল

- **react-i18next** ব্যবহার করুন।
- ফাইল কাঠামো (namespace = মডিউল):
  ```
  src/locales/en/common.json      ← ইংরেজি, কোডের ভিতরে, বাধ্যতামূলক
  src/locales/en/booking.json
  public/locales/bn/common.json   ← বাংলা, দরকার হলে আনা হয়
  public/locales/bn/booking.json
  public/locales/ar/…             ← নতুন ভাষা = নতুন ফোল্ডার
  ```
- key-র নাম অর্থ দেখে দিন: `common.save`, `booking.summary.advance`, `coa.form.name`।
- `fallbackLng: 'en'` — Local অনুবাদ না থাকলে ইংরেজি দেখাবে।
- ব্যবহার: `const { t } = useTranslation('booking');` … `{t('summary.advance')}`

### ৫.২ ভাষা বদলানো

- কোম্পানির `local_language` থাকলে হেডারে একটা বোতাম: **English | বাংলা** (Local ভাষার `native_name`)।
- বদলালে `i18n.changeLanguage()`, তারপর API-তে `users.lang` সেভ। পেজ রিলোড হবে না, পরের লগইনেও থাকবে।
- `<html lang="bn" dir="ltr">` আর `data-lang` বদলায়, যা ফন্ট আর লেখার দিক নিয়ন্ত্রণ করে।
- লগইনের পর `settings` payload-এ আসবে: কোম্পানির `local_language` (ফন্ট, দিক, অঙ্কসহ), শাখার ডিফল্ট, ইউজারের বাছাই।

### ৫.৩ ফন্ট

- `public/fonts/NikoshBAN.woff2` (ও `.woff`) অ্যাপের সাথে রাখুন।
- `@font-face { font-family: 'NikoshBAN'; unicode-range: U+0980-09FF, U+200C-200D; }` — শুধু বাংলা অক্ষরে এই ফন্ট, ইংরেজি থাকে Satoshi-তে। তাই English স্ক্রিনেও কোনো `name_local` দেখালে ঠিক ফন্টে আসবে।
- `body { font-family: 'Satoshi', var(--lang-font, sans-serif); }`
- ⚠️ ফন্ট ফাইলটা **Unicode** ভার্সন কি না যাচাই করুন, Bijoy/ANSI ভার্সন নয়।
- প্রিন্টেও (`PrintStyles`) একই ফন্ট।

### ৫.৪ অঙ্ক, তারিখ, টাকা

শুধু এই কেন্দ্রীয় ফাংশনগুলোতে ভাষার নিয়ম যোগ করুন, পুরো অ্যাপে কাজ করবে:

| ফাংশন | কাজ |
|---|---|
| `thousandSeparator` | `digit_style` অনুযায়ী ১২,৩৪,৫৬৭.০০ বা 12,34,567.00 |
| `formatDate`, `chartDateTime` | মাসের নাম ও অঙ্ক ভাষা অনুযায়ী |
| কথায় টাকা (amount in words) | প্রতিটা ভাষার জন্য আলাদা: "এক হাজার একশত পঞ্চাশ টাকা মাত্র" |

ইনপুট ঘরে বাংলা অঙ্ক টাইপ করলেও সেভের আগে ইংরেজি অঙ্কে বদলে নিন।

### ৫.৫ ডাটার নাম দেখানো

একটা কমন হেল্পার সব জায়গায়:

```ts
// lang = 'en' | 'local'
displayName(row, 'name', lang)
// local হলে row.name_local, সেটা ফাঁকা হলে row.name
```

- টেবিল, ড্রপডাউন, রিপোর্ট সবখানে এটা ব্যবহার করুন, যাতে নিয়ম এক জায়গায় থাকে।
- ড্রপডাউন/সার্চ দুই নামেই মিলবে: বাংলা স্ক্রিনে "Rahim" লিখলেও "রহিম ট্রেডার্স" আসবে।

### ৫.৬ ফর্ম

- কোম্পানির `local_language` থাকলে প্রতিটা অনুবাদযোগ্য ঘরের নিচে আরেকটা ঘর:
  - **Name (English)** — বাধ্যতামূলক
  - **নাম (বাংলা)** — ঐচ্ছিক, লেবেলে Local ভাষার নাম
- `local_language` না থাকলে একটাই ঘর, ফর্ম আজকের মতো।
- একটা কমন কম্পোনেন্ট, যেমন `<LocalNameInput field="name" />`, সব ফর্মে ব্যবহার করুন। Local ঘরে সেই ভাষার ফন্ট ও দিক (`dir="rtl"` আরবির জন্য) নিজে থেকে বসবে।
- তালিকায় "Local নাম নেই" ফিল্টার রাখুন, যাতে বাকি নামগুলো খুঁজে পূরণ করা যায়।

### ৫.৭ প্রিন্ট

- প্রতিটা প্রিন্ট বা প্রিভিউয়ে **Language: English / বাংলা** বাছাই। ডিফল্ট শাখার `print_language`।
- প্রিন্টের লেবেল আর ডাটার নাম দুটোই ওই ভাষায় আসবে, `displayName` দিয়ে।
- `PrintFooter`, `PadPrinting`-এর মতো কমন অংশ আগে করুন। প্যাডে কোম্পানি/শাখার `name_local`, `address_local`।

## ৬. সার্ভার (Laravel API)

1. **ভাষা চেনা:** ফ্রন্টএন্ড প্রতিটা অনুরোধে `Accept-Language: bn` (বা `en`) পাঠাবে। একটা middleware এটা পড়ে `App::setLocale()` করবে। প্রিন্টের অনুরোধে আলাদা `print_lang` প্যারামিটার।
2. **বার্তা:** `notFound('…')` ধরনের ইংরেজি বার্তাগুলো ধীরে ধীরে `__('booking.advance_too_large')`-এ নিন, `lang/en`, `lang/bn` ফাইলসহ। Local না থাকলে Laravel নিজেই ইংরেজি দেখায়।
3. **ডাটা পাঠানো:** API `name` আর `name_local` দুটোই পাঠাবে। কোনটা দেখাবে, ফ্রন্টএন্ড ঠিক করবে (৫.৫)। কোনো বাড়তি query লাগে না, কলাম একই সারিতে।
4. **সার্ভারে বানানো লেখা** (PDF, SMS, Excel export): একটা হেল্পার `localName($row, 'name', $lang)` — একই নিয়ম, এক জায়গায়।
5. **সেভ:** Add/Edit API `name_local`, `address_local` নেবে। ফাঁকা হলে `null` রাখবে।
6. **সার্চ:** নাম দিয়ে খোঁজে এমন সব API-তে `name LIKE ? OR name_local LIKE ?`।
7. **রিপোর্ট:** Ledger, Cash Book, Trial Balance-এর query-তে `name`-এর সাথে `name_local`-ও select করুন। আলাদা join বা query লাগবে না, তাই গতি একই থাকবে।
8. **PDF (resources/views/pdf):** বাংলা যুক্তাক্ষর ঠিক দেখাতে **mPDF** লাগবে। dompdf-এ যুক্তাক্ষর ভেঙে যায়। আগে একটা নমুনা দিয়ে পরীক্ষা করুন।
9. **Chart of Account শুরুর ডাটা:** নতুন কোম্পানির স্ট্যান্ডার্ড অ্যাকাউন্টগুলোর (Cash, Bank, Sales, Purchase, Advance Against Booking …) প্রতিটা সমর্থিত ভাষার নাম seeder-এ রাখুন। কোম্পানি যে Local Language বাছবে, সেই ভাষার নাম `name_local`-এ বসবে।
10. **Local Language বদলানো আটকানো:** কোনো টেবিলে `name_local` লেখা থাকলে কোম্পানির `local_language` বদলাতে দেবেন না (২.৪), অথবা স্পষ্ট সতর্কবার্তার পর।

## ৭. SMS

- `sms_templates`-এ `lang` কলাম (`en` / `local`)। একই `code`-এর দুটো টেমপ্লেট থাকতে পারবে।
- পাঠানোর সময় শাখার `print_language`-এর টেমপ্লেট নেবে, না থাকলে ইংরেজি।
- `{{party_name}}` একই ভাষায় যাবে (`name_local`, না থাকলে `name`)।
- ⚠️ **খরচ:** বাংলা SMS-এ এক পার্টে প্রায় ৭০ অক্ষর, ইংরেজিতে ১৬০। বাংলা SMS-এর খরচ ২–৩ গুণ হতে পারে। SMS Template স্ক্রিনে অক্ষর আর পার্টের সংখ্যা দেখান।

## ১২. নিয়মিত নিয়ম (প্রতিটা নতুন কাজে)

- নতুন স্ক্রিন বা বাটনে ইংরেজি লেখা সরাসরি বসানো যাবে না, `t('…')` ব্যবহার করতে হবে।
- নতুন key যোগ হলে `src/locales/en/`-এ ইংরেজি দিতেই হবে।
- নতুন টেবিলে নাম/ঠিকানার মতো অনুবাদযোগ্য ঘর থাকলে পাশে `<field>_local` রাখতে হবে, আর দেখাতে `displayName` ব্যবহার করতে হবে।
- `npm run i18n:check` স্ক্রিপ্ট বানান, যা `help:check`-এর মতো চলবে:
  - `en` ফাইলে নেই এমন key ধরবে
  - `.tsx`-এ সরাসরি বসানো ইংরেজি লেখা ধরবে (ধাপে ধাপে কড়া করা হবে)
  - কোন ভাষার কত শতাংশ অনুবাদ বাকি, দেখাবে
- `CLAUDE.md`-এ নিয়ম যোগ করুন: স্ক্রিনের লেখা বদলালে অনুবাদ ফাইলও বদলাতে হবে।
