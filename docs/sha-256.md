What it is
SHA-256 is a fingerprint of a file. You run the file's bytes through a standard calculation and get a fixed 64-character hex string, like:


9f2b1c...e1a4   (64 characters)
Two key properties:

The same file always produces the same fingerprint.
If even one byte of the file changes, the fingerprint comes out completely different.
Why the auto-updater needs it
Before the app runs a downloaded installer with admin rights, it computes the SHA-256 of what it just downloaded and checks it against the sha256 value your server sent. If they don't match, it refuses to run it. This protects users from a corrupted download or a tampered-with installer — the app won't execute anything that isn't exactly the file you published.

How you get it — one command on the final installer
After you build and sign the installer, run one command on that exact file:

Windows (PowerShell):


Get-FileHash -Algorithm SHA256 CopVPN-3.5.0-x64.exe
macOS / Linux:


shasum -a 256 CopVPN-3.5.0.pkg
Copy the hex string it prints — that's the value that goes in the sha256 field of your app-version-check API response (next to installer_url).

Two things to get right
Compute it as the last step — on the final signed installer you're actually hosting. Signing changes the file's bytes, so a hash taken before signing won't match.
Each OS has its own hash. The Windows .exe and the macOS .pkg are different files, so they have different SHA-256 values. Your server returns whichever matches the installer_url it's serving for that OS.
